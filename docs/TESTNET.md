# Crakbit Testnet v0.1

This document describes the first Crakbit public-development network. Coins on this network have no monetary value and the network may be reset while consensus engineering is still in progress.

## What this repository builds

The repository pins a reviewed WAM Coin reference snapshot, materializes its pinned Bitcoin Core/RandomX base, applies Crakbit-specific monetary/network parameters, mines independent Crakbit testnet and regtest genesis blocks, and compiles a node, CLI, wallet tools and CPU miner.

Crakbit testnet does **not** connect to WAM. It has a different genesis, RandomX bootstrap key, message magic, P2P/RPC ports and bech32 HRP; WAM DNS/fixed seeds are removed by the overlay.

## Consensus parameters

| Parameter | Testnet v0.1 |
|---|---:|
| Currency | CBIT |
| Block target | 120 seconds |
| Proof of Work | RandomX |
| Difficulty | DGW v3, every block, 24-block window |
| Initial subsidy | 10 CBIT |
| Halving interval | 1,051,200 blocks |
| Premine | 0 CBIT |
| Treasury | 5% of subsidy, heights 1..400,000 |
| Treasury testnet destination | unspendable burn address |
| Coinbase maturity | 100 blocks |
| RandomX epoch | 256 blocks |
| RandomX seed lag | 16 blocks |
| Testnet P2P | 29111 |
| Testnet RPC | 29110 |
| Bech32 HRP | `tcb` |

At block 1 the subsidy is 10 CBIT: 9.5 CBIT to the miner and 0.5 CBIT to the testnet treasury burn output. The treasury amount is part of the 10 CBIT subsidy, not additional issuance. The treasury stops after height 400,000.

## Ubuntu build

Install the normal Bitcoin Core/RandomX build dependencies first:

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential libtool autotools-dev automake pkg-config bsdmainutils \
  cmake git python3 libevent-dev libboost-dev libssl-dev libsqlite3-dev
```

Then, from this repository:

```bash
python3 tests/test_policy.py
CRAKBIT_JOBS=2 CRAKBIT_GENESIS_THREADS=2 bash scripts/materialize.sh
CRAKBIT_JOBS=2 bash scripts/build-testnet.sh
```

`materialize.sh` records the exact source commit, compiles the pinned RandomX library, mines the testnet/regtest genesis blocks and writes the generated values to `build/artifacts/`.

Successful build artifacts are placed in `build/dist/`:

```text
crakbitd
crakbitd-bin
crakbit-cli
crakbit-cli-bin
crakbit-wallet
crakbit-tx
crakbit-util
crakbit-miner
SHA256SUMS
```

The `crakbitd` and `crakbit-cli` wrappers force `-testnet`. `*-bin` is the compatibility binary generated by the pinned implementation and is not the documented entry point.

## Start a node

The first version intentionally starts without DNS/fixed seeds. The first node can run alone; subsequent nodes receive its address explicitly.

```bash
bash scripts/testnet.sh init
bash scripts/testnet.sh start
bash scripts/testnet.sh status
```

For another node, supply the first public peer:

```bash
CRAKBIT_ADDNODE=<seed-ip>:29111 bash scripts/testnet.sh start
```

Only TCP 29111 should be exposed for P2P. RPC 29110 is configured for localhost and should not be exposed publicly.

## Wallet

```bash
bash scripts/testnet.sh wallet default
bash scripts/testnet.sh address default
```

Back up the testnet wallet even though the coins are valueless; wallet create/restore is itself part of the test program.

## CPU mining

The miner self-test runs during the normal build. After a Stratum pool is running:

```bash
build/dist/crakbit-miner \
  -o stratum+tcp://POOL_HOST:3334 \
  -u YOUR_TESTNET_ADDRESS
```

A pool setup helper is provided separately. Solo mining remains available in the materialized reference implementation and will be validated before public testnet launch.

## Genesis verification

After materialization inspect:

```bash
cat build/artifacts/testnet-genesis.json
build/dist/crakbit-cli -datadir=build/testnet-data \
  -conf=build/testnet-data/crakbit.conf getblockhash 0
```

The returned block-0 hash must equal the `genesis_hash` recorded in the JSON artifact. Independent testnet nodes must reproduce the same genesis values from the same tagged source.

## Public-testnet readiness

Do not call the testnet public until CI has successfully completed the full materialize/build flow and at least two independent nodes have connected, mined accepted blocks, crossed a RandomX epoch boundary, restarted/reindexed successfully, and agreed on the same chain tip.

Mainnet remains a separate gated milestone. See `docs/MAINNET_GATES.md`.
